## 사용자 최적화 논의 포인트

다음 항목 의견 요청 (Phase 3 구현 전 확정):

1. **이모지 사용량** — 너무 많은가? (현재: 🔼 ⏸ 🔽 등 시각 구분용)
2. **종목 카드 길이** — 모바일 한 화면 기준 적정한가?
3. **본인 매매 기록 위치** — 카드 안 vs 별도 섹션?
4. **알림 트리거 표시 방식** — 상단 vs 카드 내?
5. **빈 칸 슬롯** — 체크리스트 형태 vs 자유 텍스트?
6. **점수 변화 표시** — `▲ 5` vs `+5` vs `📈 +5` 중 선호?
7. **언어 혼합** — 영어/한국어 혼용 OK인가? 전체 한국어 통일?
8. **누적 vs 신규** — 매일 새 노트 vs 같은 노트에 누적?

## 마크다운 → Craft 호환성

Craft는 다음을 자연 변환:
- `#`, `##`, `###` → 헤딩 (자동 토글 가능)
- `- [ ]` → 체크박스
- `>` → 인용 블록 (Craft 'Block' 스타일)
- `|...|` 표 → 일반 표 (단, Craft에서 편집 시 한계)
- `**bold**`, `*italic*` → 스타일링
- ` ``` ` 코드 → 코드 블록
- `[[링크]]` → 백링크 (Craft 임포트 시 자동 인식)

**미지원**:
- HTML 태그 (Craft에서 보임 X)
- 이미지 임베드 (자동 X — 별도 첨부 필요)

## Craft API 직접 발행 (구현됨)

> 구현 완료. `output/craft.py`는 facade로 `CraftExporter`(노트 빌더 —
> `craft_exporter.py`+`_craft_sections.py`)와 `CraftPublisher`
> (`craft_publisher.py`+`_craft_client.py`)를 re-export한다.
> `CRAFT_API_TOKEN` 발급 후 (Craft Settings → API) `--publish-craft` 플래그로 발행.
> 아래는 초기 설계 당시의 illustrative 스니펫 (실제 구현과 파일·시그니처 다름).

```python
# (초기 설계 예시 — 실제는 output/craft_publisher.py 의 CraftPublisher)
import httpx

async def publish_to_craft(content: str, folder_id: str) -> str:
    async with httpx.AsyncClient() as client:
        r = await client.post(
            "https://api.craft.do/v1/documents",
            headers={"Authorization": f"Bearer {settings.craft_api_token}"},
            json={
                "title": f"Stock Compass — {today_kst()}",
                "content": content,
                "folderId": folder_id,
                "format": "markdown",
            },
            timeout=15,
        )
        r.raise_for_status()
        return r.json()["url"]
```
